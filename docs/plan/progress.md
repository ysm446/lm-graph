# 進捗

作成日時: 2026-06-07 21:59
更新日時: 2026-06-07 21:59

## 現在の状態

LM Graph は、ローカル LLM ワークフローをノードグラフで構築するデスクトップアプリとして、基本機能から実用的な編集・生成機能まで実装済みです。

最新の履歴では、アプリ名の `LM Graph` への統一、モデル・プロジェクト一覧 UI の改善、モデルメタデータ表示、`llama-server.exe` の自動選択、VRAM 解放スクリプト、レンダラー utilities の整理が行われています。

## 完了済み

- Electron + React + TypeScript + React Flow のアプリ基盤。
- SQLite によるプロジェクト保存と、`data/` 配下への実行時データ整理。
- `text` / `context` / `instruction` / `image` ノードの作成、編集、接続。
- 型付きハンドル、サイクル防止、エッジ選択、ノード種別ごとの表示調整。
- Global / Local スコープと上流文脈の伝播。
- ローカル `llama.cpp` サーバー管理と `text` ノードへのストリーミング生成。
- 下流生成、生成キュー、生成中ノードの表示。
- 画像ノード、画像プレビュー、画像差し替え、Vision モデル向け `mmproj` 判定。
- 詳細パネルでの読み取り、編集、生成、校正。
- 校正プリセット、Custom system prompt、選択範囲校正。
- 複数ノード選択、コピー・貼り付け、インラインリネーム、キーボードショートカット。
- UI 設定の永続化、サイドバー幅、ミニマップ、スナップ to グリッド、エッジスタイル、テキストサイズ設定。
- CPU / RAM / GPU / VRAM のシステムリソースモニター。
- README、仕様書、プロンプト組み立てドキュメントの整備。

## 未完了・継続確認

- `docs/GRAPH_CHAT_SPEC.md` の永続化説明が、README の `data/` 配下保存説明と完全に一致しているか確認する。
- 画像ノードと Vision 生成のエラー表示、非対応モデル時の説明をさらに分かりやすくする余地がある。
- プロンプトログの表示と検証導線は、生成結果のデバッグ用途として継続改善する。
- 大きなグラフや長文ノードでの描画性能、スクロール、編集操作の体感を継続して確認する。
- ローカルモデル、`mmproj`、`llama-server.exe` の配置ミスに対する案内を補強する余地がある。
- 実行環境依存の機能は、自動テストだけでは確認しきれないため、手動検証手順を整える必要がある。

## 注意点

- モデル本体、`mmproj`、`llama-server.exe`、`data/` 配下の実行時データはローカル運用前提で、リポジトリには含めない。
- 生成や校正には、ロード済みモデルと `llama.cpp` サーバーが必要。
- Vision 入力は、対応 GGUF モデルと対応する `mmproj-*.gguf` が同じモデルフォルダにある場合だけ実画像を送信する。
- 未保存プロジェクトを切り替えるときは確認ダイアログを出し、保存しない場合は最後に保存された状態へ戻す。
- ユーザーの未コミット変更を勝手に戻さない。
