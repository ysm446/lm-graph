# 実装計画

作成日時: 2026-06-07 21:59
更新日時: 2026-06-07 21:59

## 現在の実装方針

- デスクトップアプリ基盤は Electron + React + TypeScript を使う。
- グラフ UI は React Flow を使い、ノード、エッジ、選択、接続、キャンバス操作を管理する。
- プロジェクト保存は `better-sqlite3` による SQLite を使う。
- UI 設定や軽量なプリファレンスは JSON として `data/` 配下に保存する。
- 生成実行はローカルの `llama.cpp` OpenAI 互換サーバーを使う。
- モデル本体、`mmproj`、`llama-server.exe`、実行時データはローカル配置前提とし、バージョン管理には含めない。

## 優先順位

1. 既存機能の安定化
   - 生成開始、モデルロード、サーバー停止、プロジェクト保存、画像読み込みなど、作業を失いやすい箇所を優先して直す。

2. グラフ編集の操作性
   - ノード追加、接続、複製、削除、複数選択、コピー・貼り付け、ズーム時表示を継続的に改善する。

3. プロンプト組み立ての明確化
   - `instruction` / `context` / `text` / `image` の順序とスコープを明文化し、実装とドキュメントを一致させる。

4. 詳細パネル中心の編集体験
   - ノードカードは一覧性を重視し、長文編集、生成、校正、保存は詳細パネルで扱いやすくする。

5. ローカル運用の見通し
   - モデルメタデータ、Vision 判定、リソース監視、VRAM 解放など、ローカル推論に必要な状態を見えるようにする。

## 今後の予定

- 仕様ドキュメントと README を最新の実装に追従させる。
- `docs/GRAPH_CHAT_SPEC.md` の保存先説明を、現在の `data/` 配下運用に合わせて必要なら更新する。
- 画像ノードと Vision 生成の失敗時表示を、より分かりやすくする。
- プロンプトログの確認導線を整え、生成時に実際へ送られる内容を検証しやすくする。
- プロジェクト保存・切り替え時の未保存状態表示をさらに分かりやすくする。
- 大きなグラフでの描画負荷、生成中の UI 更新、ノード本文表示の負荷を継続して観察する。
- Windows ローカル環境でのセットアップ手順とトラブルシュートを補強する。

## 変更時の判断基準

- 既存のノード種別、接続制約、プロンプト組み立て順序を壊さない。
- ユーザーの編集中テキストや未保存プロジェクトを失う可能性がある変更は、確認や巻き戻しの挙動を明確にする。
- UI 変更は、キャンバス、詳細パネル、左右サイドバーの役割分担を保つ。
- 新しい設定は、永続化の要否と保存先を先に決める。
- ローカルファイルやモデルに関わる処理は、存在しない場合や非対応の場合の表示を用意する。

## 検証方針

- フロントエンド、Electron、型定義に関わる変更後は、可能な限り `npm run build` を実行する。
- Python ではなく TypeScript / Electron のプロジェクトなので、通常の構文・型検証は `tsc --noEmit` を含む `npm run build` で確認する。
- 生成、モデルロード、画像入力、保存のような実行環境依存の機能は、手元のモデルや `llama-server.exe` が必要なため、検証できない場合は作業報告に理由を書く。
